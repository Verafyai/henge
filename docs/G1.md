# Gate G1: release readiness checklist

G1 is the stop after M7. Nothing below is deployed, merged, pushed to `main`, signed for production or
announced. Each item is either checked by the test suites on the `m7/release-readiness` branch or waits for Rex.

## Checked by the branch

Run from the repo root: `pnpm typecheck`, `pnpm lint`, `pnpm test`, the web and client builds, then
`pnpm --filter @swarm-explorer/web e2e` and `pnpm --filter @swarm-explorer/client e2e`.

### Catalog
- [x] The seed catalog is exactly the five approved pins, by tag, digest and size (`packages/db/src/db.test.ts`).
- [x] No moving tags, no Granite, no test-only model outside `SEED_TEST_MODELS=1` on the embedded database.
- [x] A pulled tag whose digest drifts from the pin is blocked and removed (client e2e).

### Kill switch
- [x] A platform stop and a swarm stop are signed into the revocation feed and verify against its keys.
- [x] Only platform admins can stop or restore, and only with an Idempotency-Key (web route tests).
- [x] A stop refuses new leases and qualification and cancels open leases at once, unpaid and requeued.
- [x] An idle node learns of a stop within 60 s wherever the stop lands in the poll cycle (fake timer tests).
- [x] A running task stops within 60 s, abandons unpaid and shows the signed reason (fake timer test and client e2e).
- [x] Unsigned, wrongly signed or unpinned entries are ignored; a restore lifts the stop.
- [x] With no good feed read in the last 60 s, no new work starts.

### Public results and receipts
- [x] Public results list settled work only, with counts, and no inputs, outputs, nodes, accounts or credits.
- [x] A contributor gets one signed receipt per settled result; it never changes after issue.
- [x] Receipts verify offline (`swarm receipt verify`), and any edit fails verification.
- [x] Volunteer receipts show impact and `credits: null`.

### Installer and test updates
- [x] App id `ai.verafy.henge`, scheme `henge://`, legacy schemes ignored.
- [x] The signed test manifest from `release:test` is verified, a tampered manifest is refused.
- [x] The test update downloads from a local mirror, a tampered download is refused, and the real one is staged
      only after its sha256 and size match. Nothing is installed.
- [x] Packages are test signed only (`package:internal`, ad-hoc on macOS). Nothing is notarized.

### Safety rules
- [x] Example account sign in and every `/v1/dev/*` route answer only when `devSignInEnabled()`, which is false
      on Vercel.
- [x] Credits are earned only. No purchase, transfer or cash-out endpoint exists (`api-plan.test.ts`).

## Waits for Rex
- [ ] Merge order for the open PRs, then this branch.
- [ ] Model classes and context lengths for the five pins (docs/DECISIONS.md, M7 Needs Rex).
- [ ] Production custody of the revocation and receipt keys, and the client's pinned revocation keys.
- [ ] Who may use the kill switch in production, and whether a second approver is required.
- [ ] Whether receipts should carry the contributor's account id.
- [ ] A release host, then Apple and Windows signing and notarization (docs/CERTIFICATES.md sections 1, 2 and 5).
- [ ] Production hosting and the go ahead to deploy.
